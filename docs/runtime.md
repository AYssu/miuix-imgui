# 调度、后台任务与长列表

## 按需重绘

组件通过 `skui::CurrentFrameRequest()` 报告本帧是否还有动画，以及下一次定时重绘的最短延迟。
`RequestAnimationFrame()` 请求持续绘制；`RequestFrameAfter(seconds)` 合并为最早的有限非负延迟。
提示属于当前 ImGui context / frame，下一帧自动清空。每个 context 首次使用分配一个小状态，
由 context 销毁钩子释放；连续调用不分配内存。所有接口均在渲染线程使用，不会自行启动线程或定时器。

```cpp
ImGui::NewFrame();
DrawApplication();
ImGui::Render();
SubmitAndPresent();
auto request = skui::CurrentFrameRequest();
// 宿主结合输入队列、request.continuous 和 wake_after_seconds 决定等待时间。
```

自定义动画要在未结束时请求重绘。已接入组件的按压 / 选择 / 折叠、侧栏、弹层、子菜单、路由、
数字选择器惯性、面包屑定位、Tooltip 和 Snackbar；无动画主题下不为静止的不定进度环持续重绘。
宿主仍应根据自身平台输入与渲染后端决定调度，不能只根据组件提示休眠。

Android Gallery 默认在静止时以约 100 ms 为周期检查状态。触摸队列和后台结果通过 `eventfd` 唤醒，
IME 通道直接参与 `poll`；输入后保留 250 ms 活动期，文本编辑、按住及持续动画期间正常绘制。
等待前已经发生的通知仍保留；触摸样本用两块容量保留的缓冲区交换，队列上限 1024，满时保留最终状态。
唤醒对象先于生产线程创建，所有生产线程停止并 join 后才销毁。创建唤醒源失败时继续连续绘制。
`--continuous` 可暂时禁用闲置降帧，便于在同一场景比较。

100 ms 检查是当前悬浮窗口宿主的保守选择，方向变化及维护任务最迟下次检查处理；
没有证明所有平台可无限期停止绘制。首次从闲置唤醒时，新按压 / 展开目标的首步最多推进 1/60 秒，
避免将之前的闲置间隔当成新动画已经播放的时间。

## 任务与数据归应用所有

Gallery 首页“应用基础 → 任务与长列表”展示加载 10000 条记录、进度、取消、模拟错误和重试。
实现见 [data_model.h](../examples/gallery/data_model.h)、[data_model.cpp](../examples/gallery/data_model.cpp)。
这是示例的数据模型，不是组件库的全局任务池：

- 第一次请求才启动一个 worker；最多保留一个待处理请求和一个结果，记录数限制在 1～100000。
- 新请求、取消或离开页面都会更新 generation；旧结果即使已经生成，也不能在之后交给 UI。
- worker 只处理普通数据和线程安全的唤醒回调；ImGui、列表过滤和 UI 状态更新都在渲染线程执行。
- 模拟 I/O 使用可中断等待；构建记录时分批检查取消。退出显式停止、唤醒并 join，之后注销回调。
- 失败和取消保留已显示的数据。真实项目应替换模拟 I/O，并为自己的阻塞 API 提供取消及超时。

过滤 / 排序仅在数据或条件改变时重建索引。`ImGuiListClipper` 每帧只提交可见行，
`PushID(record.id)` 使控件身份与排序位置无关，选中项记录业务 ID。
重建索引前保存可见记录 ID 和行内偏移；记录仍存在时恢复锚点，接近列表末尾时受可滚动范围限制。
此示例采用固定行高。动态行高应使用相应测量 / 缓存方案，不能直接沿用这里的高度计算。

## 验证记录 · 2026-11-25

`skui-runtime-tests` 验证 context 隔离 / 销毁重建、连续提示零分配、定时提示、闲置唤醒的折叠首步、
动画结束后停止持续请求；另覆盖任务替换 / 取消 / 失败重试 / 丢弃已发布旧结果 / join，
100000 条记录的过滤、排序、稳定 ID、滚动锚点及每帧少于 16 行的裁剪。
Linux 上额外检查通知合并、等待前通知、线程唤醒与 IME 类文件描述符。
GCC / Clang、ASan + UBSan、独立 consumer 和 Android 两个目标均通过；
同一组运行时 headless 回归也在下述 Android 真机原生运行通过。

小米 Android 13 / Vulkan / 1080×2400 实测首次触摸导航、10000 条记录加载、选中后排序与搜索，
系统键盘正常唤起并回填 `00001`；过滤后仍选中记录 #1，只有一行参与绘制。
相同首页的单次约 4 秒静止采样中，`/proc/<pid>/stat` 用户加系统 CPU 时间为默认调度 19 ticks、
`--continuous` 148 ticks（CLK_TCK=100，采样时长分别约 4.06 / 4.11 秒）。
该短样本约减少 87% 的进程 CPU 时间，不是帧延迟或物理功耗测试，GPU / 系统服务开销未计入。
两次正常退出日志均为 0 字节，测试进程、临时上传文件及 IME 辅助包均已清理。
