## 建议实施顺序

优先级以复用收益和可验证性排序，表示建议顺序，不是发布日期承诺。

### 第一批：设计参数、设置保存、可观测性

1. **统一设计参数**：在现有 Theme 上补充语义色与排版、间距、圆角等参数，再迁移组件读取入口。
   验收：默认主题维持现有效果；修改一个语义参数后相关组件一致更新；局部覆盖退出后恢复；
   浅深色、缩放、禁用及弹层都覆盖回归；继续保留宿主字体缩放。
2. **可选设置持久化**：先保存 Gallery 的外观、动画、触觉与窗口几何，明确用户主动保存或宿主启用自动保存的时机。
   验收：重启能恢复；文件缺失、损坏、旧版本与未知字段均有确定行为；写入失败保留有效旧配置；
   存储路径和文件访问由应用决定，组件绘制函数保持现有调用约定。
3. **性能与交互诊断面板**：记录 CPU 阶段耗时、帧间隔 p50 / p95、顶点与纹理数量，显示当前焦点、活动项和弹层。
   验收：能定位一次拖动或 Glass 的耗时；有界采样、统计可关闭；分别记录 CPU 工作耗时与帧间隔，
   GPU 时间单独标注其测量支持情况；普通用户页面保持简洁。

这批完成后，以 Gallery 演示“统一修改外观 → 保存 → 重启恢复 → 查看性能”的完整路径。

### 第二批：布局、输入和运行效率

1. **自适应与字体规范**：建立宽度断点与安全区域协议，增加动态字号、长翻译文本、键盘遮挡和横竖屏示例。
   验收：窄屏 / 宽屏与字号变化后没有意外裁切、重叠或失去可点击目标；平台信息由宿主传入。
2. **键盘与焦点**：检查所有自绘控件的导航入口，统一弹层开关前后的焦点恢复及返回键处理。
   验收：典型设置页面可通过 Tab / 方向键 / Enter / Escape 完成操作；触摸手势保持可取消，退出中的控件不接收输入。
3. **闲置降帧与长数据示例**：在 Android Demo 宿主建立活动 / 动画 / 闲置调度，再评估是否抽出通用辅助接口。
   验收：静止时降低绘制频率；输入、IME 回填、任务结果及持续动画能及时唤醒；
   使用 ImGui 已有裁剪工具展示大量数据，检查排序和过滤后 ID、选中项与滚动位置的稳定性。
4. **异步示例**：以可取消的数据加载展示进度、失败与重试，记录线程、对象和退出的所有权。
   验收：加载不阻塞触摸与绘制，离开页面后的旧结果不覆盖新状态，退出时不留下后台任务。

### 第三批：开发工具与交付

1. **交互调试工具**：围绕当前 Gallery 增加控件定位、状态检查和动画调试入口，补全高层交互自动化。
   验收：复现问题时能报告控件 ID、状态和输入序列；诊断与测试产物留在忽略目录。
2. **可安装 CMake 包**：增加 install / export 与独立 find_package consumer，覆盖随库 ImGui 和宿主 ImGui 的接入边界。
   验收：安装后将包移动到另一目录，外部工程仍能编译运行；导出文件不含本机源码 / 构建路径；携带所需许可。
3. **可选桌面宿主**：复用成熟 ImGui 平台后端，提供能交互运行 Gallery 的桌面示例，帮助贡献者验证。
   验收：Android 工具链仍为可选项，现有离线 headless 测试继续可用；逐个平台建立实际验证记录。
4. **兼容与发布规范**：整理公开 API 版本、变更记录、固定依赖、发布校验和及设备 / 系统 / 后端矩阵。
   验收：编译验证与运行验证分别记录；发布内容可以从固定提交和工具链重新构建。

## 后续单独评估

- **GPU Glass**：先定义渲染器回调、纹理生命周期和 CPU 回退，再以当前画质回归比较 GPU 路径。
  用目标设备的画质、帧耗时和资源占用决定是否默认启用。
- **屏幕阅读器与复杂文字排版**：键盘焦点、翻译表各自只能解决部分问题。
  Android 屏幕阅读器需要语义节点与平台桥接；复杂文字排版和双向文本需字体 / 排版系统支持，分别建立验收。
- **可视化编辑器与热重载**：先完成设计参数和调试预览，再评估代码生成或编辑器接口。
  任意 C++ 绘制逻辑热替换属于独立工程，不作为主题预览的隐含要求。

业务状态和文件访问继续由宿主拥有；布局、设计参数、交互协议与平台适配应有明确边界。
对已有 ImGui 能力优先做一致性适配与示例验证，再决定是否需要新的公开封装。
